# Domain documentation

This project uses one shared domain context.

## Before exploring or changing code

Read the root `GLOSSARY.md`, then relevant decisions under
`docs/adr/`.

If these documents do not exist, proceed silently.
Domain modeling creates them when terms or decisions are resolved.

## Locations

- Shared terminology: `GLOSSARY.md`.
- Architecture decision records: `docs/adr/`.

## Vocabulary

Use glossary terms consistently in specifications, tickets,
code, tests, and explanations.

When a needed concept is missing, assess whether it belongs
in the domain model and raise it during domain modeling.

## Decision conflicts

Explicitly identify any proposal that conflicts with an
existing ADR. Explain the conflict and the reason for
reconsidering the decision.
