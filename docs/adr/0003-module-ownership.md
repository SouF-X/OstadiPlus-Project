# Keep business ownership explicit inside the monolith

On 2026-10-31 the developer accepted eight initial business areas: Identity and organizations, Relationships and access, Content, Media and offline, Learning, Student finances, Teacher billing, and Operations. Organize them as feature groupings within the four agreed Clean Architecture projects, initially sharing PostgreSQL; each area owns changes to its records, with other areas coordinating changes through explicit Application contracts and ordinary in-process calls where appropriate. This preserves distinct authorization, content/media, and financial rules while keeping implementation manageable; first-workflow entity/tenant boundaries, cross-module transactions, and reporting reads remain to be refined in the [business-module discussion](../../.scratch/ostadi-engineering/issues/02-business-modules-and-data.md).
